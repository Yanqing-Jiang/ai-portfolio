## Immediate Remediation Plan (dataset receipts + OpenAI Agents–aware follow-up routing)
1. **Guarantee dataset receipts at SQL completion (planner + agent flows).** Keep the existing `_persist_session_state(..., record_dataset_preview=True, record_artifacts=True)` call in the planner SQL lane and extend coverage so any OpenAI Agents–prefilled `SQLExecutionArtifact` (for example, hydrated from `revision_snapshot` or executed via `AgentRuntime`) is followed by `_planner._persist_session_state(..., record_dataset_preview=True, record_artifacts=False, record_sql=False)` when SQL results are fresh. This ensures `planner_dataset_preview` and dataset receipts exist for all single-agent planner executions, regardless of whether the planner or the agent runtime “owns” SQL.
2. **Allow downstream lanes to backfill previews.** Rely on the extended `_persist_session_state` logic so `record_web=True` (and other non-SQL flags) still serialize dataset previews whenever `ctx.artifacts.sql_execution` exposes either preview rows or a normalizable `row_count`. This plugs the ledger gap where the web lane persists first and previously logged `analysis_lane_missing_artifact` despite having `row_count: 12` in memory.
3. **Hydrate manifests on the authoritative session snapshot before routing follow-ups.** Introduce a `hydrate_inputs_manifest(session_id, repository)` helper (or equivalent `RevisionContext.load` hydration) that:
   - Loads the `SessionStateSnapshot` once,
   - Applies `ensure_analysis_lane_receipts()` + `refresh_analysis_inputs_manifest(persist=True)`, and
   - Saves the updated snapshot back to the repository.
   Have `analytics_memory_workflow` call this helper whenever `analysis_revision_requested` is true and `analysis_inputs_manifest.status != "sealed"`, then construct `RevisionContext` from the hydrated snapshot so manifest state, not transient lane flags, decides between `baseline_still_streaming` and `cannot_revise`.
4. **Align OpenAI Agents SDK session memory with analytics sessions.** In `AgentRuntime` / `AgentMemory`, ensure each analytics `session_id` maps to a single Agents SDK session/thread and that `record_agent_run` persists run IDs, traces, and tool receipts into the same `SessionStateSnapshot`. Enforce a 30-minute idle timeout and “new chat” behavior by:
   - Resetting or dropping the existing `SessionStateSnapshot` (including `tool_cache["agent"]`, manifests, and lane receipts) when the frontend starts a fresh chat, and
   - Avoiding reuse of previous Agents sessions across distinct chat flows.
   This keeps agent memory strictly scoped to a single analytics session and prevents stale manifests from leaking into new chats.
5. **Regression coverage + verification (single-agent flow).** Extend `backend/tests/analytics/test_session_state_receipts.py` with a planner-specific test that simulates a single-agent, web-first persistence order where dataset receipts are present but manifests are initially unsealed, and assert that manifest hydration seals inputs without losing receipts. Add a revision routing test in `backend/tests/analytics/test_revision_routing.py` that:
   - Seeds a single-agent snapshot with valid `planner_dataset_preview` + web/market receipts but an unsealed manifest,
   - Runs `analytics_memory_workflow` for an analysis revision, and
   - Asserts the SSE stream emits `baseline_still_streaming` (and never `cannot_revise`) until the hydrated manifest seals.
   Capture and attach a fresh single-agent ledger (for example, `docs/agent-process-ledger - 2025-11-14T22xxxx.xxx.json`) after these changes land to demonstrate that `follow_up_route/cannot_revise` no longer appears when dataset receipts and manifests are healthy.

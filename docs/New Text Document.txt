0. Target State in One Picture

Anchor this as the “endgame” you’re heading toward:

FlowMode.DIRECT

Stays as is: deterministic SQL → chart → web/market → analysis via PlannerExecutorFlow.events().

No session memory hydration, no agents, used for “instant answer” demos only.

FlowMode.SINGLE_AGENT

Both fresh and revision runs go through AgentRuntime with a single planner agent.

Planner agent calls tools that wrap your existing lanes (sql_lane, chart_lane, fanout, analysis_lane, revision tools); PlannerSequencer is only used under the hood for DIRECT.

FlowMode.MULTI_AGENT

A supervisor agent (manager) orchestrates lane-specialist tools via the Agents SDK manager pattern:

sql_specialist, chart_specialist, web_specialist, market_specialist, analysis_specialist, revision_specialist.

Specialists are implemented as function tools backed by your existing Python modules and run under a single supervisor run.

Sessions + guardrails

Sessions use OpenAI Agents sessions + your existing SessionStateSnapshot to share state across runs.

Guardrails live at the agent level (input/output policies) plus your existing business guardrails in SupervisorRetryManager, FollowUpClassifier, and tool-specific policies.

No new feature flags. DIRECT remains your rollback path. Single- and multi-agent modes move to “agent-only” once you’ve walked through the phases below.

5. Suggested Implementation Order

If you want a blunt ordering that minimizes thrash:

Tool layer first

Build ToolDefinition, run_tool_by_id, and rewire PlannerToolRegistry + Agents manifests to consume it.

Single-agent fresh → agentic

Fresh runs in FlowMode.SINGLE_AGENT go through AgentRuntime with the fresh plan.

Supervisor + specialists-as-tools

Turn MultiAgentFlow into a supervisor + *.asTool() pattern; stop calling planner directly from supervisor modes.

Revision unification

Enforce agent-only revisions; delete planner revision branches in analytics_memory_workflow.

Frontend consolidation

Normalize event consumption to the agent schema; update WorkflowCanvas + ProcessPanel + LiveArtifacts.

Legacy removal

Sequential pipeline deletion, flag cleanup, compatibility shim removal.

At the end of this sequence you have:

DIRECT = deterministic baseline.

SINGLE_AGENT = planner agent over shared tools.

MULTI_AGENT = supervisor + specialists-as-tools.

One tool registry, one SSE schema, and no planner-based revision paths left to maintain.

If you want, next step after this is to design a “planner agent” on top of the supervisor stack (optional), but you don’t need that to get to a clean, modern agentic architecture.
